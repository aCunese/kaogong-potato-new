## 4. 设计决策

### 4.1 同步

复用现有 store、事务与 lease/fence。异步 hash 在事务外，提交时在 snapshots/outbox/sync_state 的短事务内核对 revision、contentHash、基线和观察到的任务集合。只合并从未投递且已被快照覆盖的任务；不可锁住整个 HTTP 过程阻塞正常登记。

任一任务曾 claim/投递后，其 requestId 与完整语义 payload 绑定。重试复用冻结 body，认证 header 可更新，attempt/lease/backoff 可变。新内容使用新 requestId。未知提交结果先确认原请求，不能改成新内容重试。

成功状态同时要求无未决任务/冲突、本地 hash 与可信确认基线一致。普通 pull 和服务端快照安装事务也验证本地没有新写入；现存用户资料没有可信基线时保留本地、建立可处理冲突，不猜测它是可覆盖缓存。不存在本地快照、首次空白或已经由服务端核实的初始化沿用原初始化流程，不能误制造永久冲突。

### 4.2 导入

导入入口创建 OperationContext，全程复用。executeMutation 可接收原 context，禁止重新取得新账号身份包装旧操作。导入提交事务先保存实际将被覆盖的快照为恢复点，再更新 snapshot/outbox/media，任一步失败全回滚。沿用 Schema 3，不以删库或改命名空间绕过兼容。

### 4.3 附件

ensureAttachmentFile 成功意味着最终文件 size/hash 正确；任何失败向调用方传播。统一新上传和去重自愈语义，失败不返回可用 media URL。补偿只能处理本次新建资源，不删除其他记录仍引用的文件。

### 4.4 恢复互斥与输入校验

采用 Unix 内核文件锁，而非 PID/超时猜测：Node 启动小型 Python3 helper，使用 fcntl.flock 非阻塞共享/独占锁，READY 握手后才允许 DB 操作。helper 持有固定锁文件 FD，等 stdin EOF 释放；父进程退出或 SIGKILL 会关闭管道。锁文件永不删除/替换。Linux 镜像保留当前构建阶段已有的 python3；Mac 使用现有 python3。不新增 npm 生产依赖。

server/普通 DB CLI/备份持 shared，restore 持 exclusive；恢复不先拿 shared 再升级。helper 意外死亡必须停止写服务。restoreOffline 改为 async，所有调用方 await。启动/停止、SIGTERM、失败清理均遵循先关闭 DB 后释放锁。

这是约束项目自身所有运行入口的协作锁，不声称能阻止任意外部 SQLite 工具绕过协议。

源备份先按明确的应用表/列和 manifest 校验，不调用会建表的 getDb 假装“修好”源库。支持当前 Schema 3 及代码明确声明并经过测试的旧形态；未知结构/未来 schema 拒绝。若兼容旧备份，只在 staging 进行已定义的非破坏性补列，再重新完整验证。

源与 staging 校验当前工作区及历史 JSON、媒体归属/引用/大小/SHA、外键；staging 完成代际轮换和会话撤销后再验证，才原子替换主库。目标卷目录和锁 inode 不替换，保留恢复前安全快照。恢复后需重新登录，不能承诺无感登录或任何故障下零丢失。

### 4.5 备份交付与小功能

先修导入身份再开放设置入口。Android 增加可选备份导出 capability，保留原 bridgeProtocol 与安装状态机。SAF ACTION_CREATE_DOCUMENT 在 UI 线程，字节写入在后台；最多一个 operation，分块/确认、总大小上限、最终字节数/SHA 校验、取消与终态 fence。新增备份专用 window.__kaogongBackupExportEvent，不能覆盖 window.__kaogongAndroidEvent 或写入 APK 安装终态。

普通浏览器可返回“已发起下载，请检查下载目录”，不能声称已确认磁盘文件。Android 仅收到保存成功终态后成功；旧 APK 不支持新 capability 时给出系统浏览器导出入口，不重复使用无效 blob 下载。

JSON 仍限制 50 MiB、单图10 MiB，媒体默认配额500 MiB；不做ZIP分卷。导出按 UTF-8 实际总字节校验，40 MiB 起提醒，超限完整拒绝且不删照片。内部媒体必须内联；历史 https 外链可在客户端经 CORS 读取并内联，失败则明确指出来源并拒绝“离线全量”成功，服务端不新增任意 URL 抓取。

错题非长图保持1200×1200、quality=0.75；长短边比大于2时改用长边4096、短边1200的包围盒，输出短边不得小于 min(原图短边,720)，超长图无法满足则提示裁剪/分段，不默默压成不可读图片。头像规格不变。保留用户手机原文件。

冲突隐藏只改变 UI 展示，不清 conflictData/IDB conflict/outbox；按 userId+generation+revision+hash 区分同一冲突。显示日程、记录、错题条目及照片引用数量；文字不再把全部 plans 称作“今日日程”。登记成功有错题时可直接打开现有拍照弹窗并预选题本，不自动更改统计。

### 4.6 版本与部署

候选目标：Web/Android 1.0.5，Android code6，Web build20261027.04。实施前读实际线上和已分发版本；若已有相同或更高值，统一分配更大的 code/build。日期跨天使用执行日构建号，始终单调递增。同一 build 不交付不同内容，代码回滚也使用更高 build。

生产单独 compose.prod.yml：不可变 APP_IMAGE、已核实绝对 PROD_DATA_DIR、回环端口、非root、healthcheck和日志轮换。脚本/APK随镜像交付，避免宿主旧脚本覆盖新镜像。先构建验证再切换，不在切换时临时改数据结构或换空目录。

Web 首次可用、回前台、联网及手动检查沿用现有逻辑，30分钟是节流，文档不承诺后台定时刷新。更新必须遵循计时、冲突、待同步和未保存输入保护；不自动清站点数据、注销、删库或强制重载。

至少部署前及部署后各一次有效热备，并有一份可恢复的异机副本。既有周期备份继续使用；没有定时作业时配置每小时热备。异机路径由实际可用设施决定，已配置Restic则校验后使用，未配置可取回 tar.gz；不因没有Restic阻止少量用户发布，也不把本机备份当异机备份。24小时全部/30天每日/8周每周归档策略保持，最近7天全部工作区历史保持。
