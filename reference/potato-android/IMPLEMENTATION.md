# Potato Android UI Design Preview

Goal: Deliver independent Android UI design images and a browsable design gallery covering all eight existing modules and essential flows.

Updated visual direction: user supplied cream/sage reference screenshots and a yellow potato mascot. This supersedes the previous blue palette. Preserve existing functionality and use illustrative demo data.

Canvas: 412x915 logical units, exports at 2x. Check 360x800. Warm cream #F4F3EB, paper #FFFDF8, sage primary #61794F, ink #343C2F, secondary #697160, line #E4E6D9, soft sage #E7EDDF, potato gold #E6B957. Noto/Android compatible sans-serif, body 14-16, title24, main metrics28-32.

Architecture: independent HTML design prototype in this directory. Existing product source and APIs are untouched. Shared CSS and SVG icons; generated potato illustration sheet used as CSS sprites. Per-screen images generated by browser rendering, preserving crisp Chinese typography.

File interfaces:
- ui.js defines window.PAGES = {}, I(name,size), potato(pose,extraClass), button(text,icon,kind,go), field(label,value,hint), subjectTags(active), studyTabs(active), analysisTabs(active), section(title,right), metric(value,label), arrowRow(icon,title,sub,go,end).
- learning.js / analysis.js / account.js add objects to window.PAGES. main-pages.js adds remaining pages.
- Page object: {title, eyebrow?, subtitle?, tab:'today'|'study'|'wrong'|'analysis'|'mine', back?:string, noNav?:boolean, mascot?:number, body:()=>HTML, footer?:()=>HTML}. Optional headerAction:{icon,go}. body contains main content only, no statusbar/header/navigation.
- Each script loads before app.js; helpers are available. Links use data-go='screen-id'.
- #phone is the screenshot target. ?screen=ID shows a single full-size screen. Default is gallery. ?board=core shows 8-page overview. ?board=flows shows supporting flows.

Do not add online question banks, AI/OCR, course playback, payments, social, or learning streaks. Show screenshots as demo data, no real account changes.

Verification: syntax checks, browser rendering, inspect all screens for horizontal overflow and missing assets, inspect key flows and 360-width adaptation, verify all PNGs exist. No production tests or build needed for this isolated visual preview.
