# 考公工作台 · 土豆陪伴版：完整 Android 复刻 Prompt

请读取上方 Figma Design 中的可编辑设计，完整复刻「考公工作台」Android 应用的界面、信息层级、页面关系和交互。目标是可以继续开发、检查功能和交付的完整产品，不是风格海报、若干首页示意或把设计截图铺进手机框。以下要求可独立作为完整需求使用。

## 一、依据、优先级与交付边界

最新视觉以「奶油白、鼠尾草绿、黄色土豆吉祥物」的 Figma 设计及本 prompt 为准。此前材料中出现的墨蓝、冷灰专业风格已被覆盖，严禁沿用旧墨蓝主色、旧猫咪素材或旧桌面侧栏。

先检查 Figma 的页面、Frame、组件、变量、Auto Layout 和原型连线，再逐页实现。若当前工具无法读取链接，请如实标明读取限制，不要声称已经检查。已有 28 个基础设计画面与 22 个补充功能/状态画面是复刻基准，未画出的异常与加载状态需按同一设计系统补成组件变体，不得把“没有单独截图”当作遗漏功能的理由。

本产品是个人备考执行与记录工具：将纸质题本、外部网课和自定义事项，连接到今日计划、计时、完成登记与统计复盘。仅保留这些实际业务，不添加在线题库、题目正文库、自动批改、AI、OCR、内置播放器、课程购买、会员支付、考试报名、社交、排名、成绩预测、连续打卡或学习目标系统。

区分三类内容：①原有业务能力，必须完整保留；②当前设计稿的演示数据与跳转，用于展示，不代表已连接真实服务；③下面提出的错误反馈、账号隔离、离线存储、Android 文件与安全区适配，是待实现和待验证的要求，不能写成原系统已经完成。不得未经授权连接真实账号、上传图片、覆盖线上状态或调用生产 API。

## 二、视觉系统与 Android 画布

- 主画布 412×915 逻辑尺寸；逐页校核 360×800、393×873。设计单位近似 dp，正文用可缩放字体；不能把 824×1830 的双倍导出图当作逻辑尺寸。
- 颜色：奶油白背景 `#F4F3EB`；纸白表面 `#FFFDF8`；鼠尾草绿主操作 `#61794F`；主文字 `#343C2F`；次文字 `#697160`；分隔线 `#E4E6D9`；浅绿 `#E7EDDF`；土豆黄 `#E6B957`。危险操作使用克制的暖棕红，颜色同时配文字与图标。
- 使用 Noto Sans SC / Android 兼容中文无衬线，数字可配 Roboto。正文 14–16，页面标题约 24，主要指标 28–32，首页核心分钟可适度放大。辅助说明保持清楚，不以大面积 10–11 号字容纳功能。
- 页面横向边距 20，小屏 16；以 4/8 间距体系组织，主要区块留白 20–28。圆角约 12–24，细线分隔、少量纸白表面，不给每段文字都套厚卡片。不添加玻璃模糊、重阴影、霓虹或大面积渐变。
- 首页核心是今日执行；统计页核心是可信数据；账号页核心是状态与操作。土豆作为视觉陪伴，不遮住题本名称、表单、数值、图表或按钮。参考图只用于视觉判断，不提取其中的私人信息。
- 主触控区至少 48×48dp，主按钮约 52dp。顶部应用栏、底部导航、状态栏与系统手势区分层；当前预览中的状态栏约 30、页头约 84、底部区域约 90 只是设计占位，不可硬编码为所有设备的系统高度。

土豆角色保持黄色不规则椭圆身体、棕色手绘描边、圆眼、橙色脸颊、细黑手脚和透明背景。制作八种动作：0 挥手、1 读书、2 戴耳机、3 用放大镜查错、4 展示图表、5 使用电脑、6 庆祝、7 写笔记。各动作比例与画风一致。吉祥物和演示照片可使用独立图片资源，文字、表单、图表和整个页面不能合成为图片。

## 四、八模块功能与表单，逐项保留

### 1. 今日计划、三类登记与计时

首屏显示今日已累计分钟（包含已暂停任务的累计 actualMinutes；分析仍只读取完成登记记录）、完成数/计划数、紧凑横排三考试倒计时和可执行任务。考试固定「事业编、国考、省考」，点击对应项编辑其日期，不能把考试类型变为任意新增字段。空日期显示「未设置」，过去日期显示 0 天；日期选择、选中、取消、保存均可操作。

从事项库选择一个事项加入今天，填写计划分钟；日期固定当天，不添加未来排期、重复任务、历史日历或补录。保留题本、网课、自定义三种来源标记、科目、名称、计划分钟、实际累计分钟和运行状态。任务有未开始、计时中、已暂停、已完成；完成后不能继续计时、重复登记或撤销完成。删除计划不撤销已经产生的学习记录和累计进度。

计时为正向累计，不是番茄倒计时；计划时长不代表到点自动结束。显示本段计时与此前累计的区别。退出计时页或临时离开应用不应默认暂停。原系统允许多项同时计时，不得静默改成单任务互斥；需要清楚展示每项状态。跨天后正在运行的任务仍应可见、可暂停和完成，这是待完善的实现要求，不新增排期能力。

完成必须进入正确表单：题本填写「本次做题数、本次错题数、实际分钟」；网课填写「本次完成课时、实际分钟」；自定义显示只读「事项、科目」，填写「实际分钟」。可手动调整时间。错题数不能超过做题数，数值不得为负；必填缺失时定位字段并禁用提交。计时暂停、保存进行中、防止连点重复登记、保存失败后保留输入都要有状态。成功反馈按本次类型展示数据，更新今日汇总和对应来源进度。

### 2. 事项库

每本题本、每门网课各自动对应且仅对应一个来源事项，显示类型、科目、默认分钟和「加入今天」。删除来源时移除对应事项；不得独立新增、删除或改成另一个来源。自定义事项表单包含「名称、八科之一、默认分钟」，支持新增与删除，保留原先没有自定义名称/科目编辑入口的边界。默认分钟可调整，在加入今天时也可再调整；保存值不应在重新构建映射后被重置，此处需修复原有缺陷。

初始资料为 14 本题本、7 门网课，对应 21 个来源事项；演示另加一条自定义可显示 22 项。不要让数量和实际列表互相矛盾。不新增搜索、科目筛选或复杂排序作为既有功能。

### 3. 题本进度

列表显示名称、科目、已做/总题数、进度、错题数、正确率和平均分钟/题，保留新增、编辑、删除。完整表单字段为「名称、科目、总题数、页数、已做题数、错题数、累计分钟」，不能为追求简洁漏掉页数或累计值。页数是保存字段，不声称有自动页码进度。

正确率＝（已做题数－错题数）÷已做题数；平均分钟/题＝累计分钟÷已做题数。题量为 0 时显示未产生数据，避免 NaN 或无依据的 100%。累计编辑要求非负且逻辑一致，错误不能大于已做题数，其他超限策略需在实现中明确。直接改累计值不创建或回填学习记录，表单需有短说明。

删除确认说明会移除题本及其事项，保留历史学习记录和已有计划；对来源已删除的未完成计划显示不可登记原因。相关错题照片不能静默消失，需以「原题本已删除」的归属状态继续可见，这是修复数据可见性，不是新建照片分类系统。

### 4. 网课进度

列表显示名称、科目、已完成/总课时、进度、累计分钟、编辑和删除。完整表单包含「名称、科目、总课时、已完成课时、累计分钟、课程链接」。链接只接受有效 http/https；有链接时交由外部网页打开，无链接时显示「未设置课程链接」，不能放可点击但无反应的播放图标。

课程是外链记录，不是内置播放器；没有课程目录、观看识别、自动完成课时或购买。完成网课任务累计课时和分钟；直接编辑累计值不回填学习记录。来源删除、数值校验和确认规则与题本保持一致，不能误删历史登记。

### 5. 错题照片复盘

按题本分组展示照片缩略图、日期、复盘原因摘要、详情和删除。导入流程包含「所属题本、系统图片多选、复盘原因（选填）」；展示已选张数、预览、取消选择、处理进度、失败原因和重试。每张图保存一条记录，同批照片共用原因。没有题本时先引导建立题本，取消系统选择器不创建空记录。

照片沿用长边最多 1100px、JPEG 质量约 0.72 的压缩逻辑，作为内嵌图片随工作台数据保存。详情可看完整大图和多行原因，设计可支持缩放查看，不增加照片文字识别、笔迹标注、标签、备注编辑、掌握度或复习计划。删除同时移除照片记录，但不修改题本数值错题数；确认中说清影响。图片加载中、损坏、处理失败、批量部分成功、本机空间不足都需要反馈，已成功记录不得因后续一张失败丢失。

### 6. 总体分析

提供最近 30 天、最近 90 天、全部记录切换，显示八科学习分钟分布和各科每日正确率曲线。八科完整枚举：资料分析、判断推理、言语理解、数量关系、政治理论、常识判断、申论、面试；申论和面试只是同一套科目选择，不新增专属评分流程。

图表只聚合已完成登记生成的 `records`。时间环图与图例覆盖八科，图例同时给分钟；曲线按日期、科目汇总，正确率用该日期该科的总做题数与总错题数计算。可用图例高亮改善移动阅读，不伪造没有题量记录的曲线。只有分钟的科目仍计入时间分布，其正确率标「暂无题量记录」，不能显示成 0%能力。

日期范围按本地自然日包含首尾日；最近 30/90 天需修复原边界少一天的问题。无记录显示空态与登记引导，只有时长显示时间图和题量缺失说明，避免空坐标轴冒充趋势。图表用可编辑矢量与真实数据绘制，不用截图，轴、图例、单位和选中反馈在小屏仍可读。

### 7. 每月分析

可选择年份与月份，展示总分钟、总题量、总错题、整体正确率，以及八科正确率和各科分钟。整体正确率＝（本月总题量－本月总错题）÷本月总题量，必须按题量加权，不能平均八科百分比。无题量时正确率为「— / 暂无题量记录」；0 分钟与没有记录的描述需清楚。

课程和自定义的完成分钟计入分析，但不能因此增加题量；尚在计时或尚未完成的计划不计入 `records`。题本/网课页面的累计数可被手动修改，不保证与分析一致；照片条数也不是数值错题数。月度页必须保留这些统计边界，不能新增热力图、连续天数、同比环比或目标达成率。

### 8. 我的、认证、同步、备份与资料

登录与注册只有「用户名、密码」两字段。注册沿用用户名至少 2 字符、密码至少 4 字符；用户名去首尾空格并转小写，与现行服务保持兼容。不要增加手机号、邮箱、验证码、忘记密码、密码修改、账号注销或同意条款勾选项。展示用户名 `potato_01`，显示名称「土豆的备考空间」，两者不可混为同一字段。资料编辑只包含显示名称和从相册选择头像。

未登录时说明当前仅保存本机，仍可学习和 JSON 备份；已登录展示账号、最近同步时间和真实状态。主同步使用自建用户名 API，不接旧 Supabase 邮箱、Storage 或照片迁移占位代码。保留上传本机、从云端拉取和退出账号。上传覆盖云端、拉取覆盖本机，均需具体确认并提供先导出备份的入口；云端空、登录过期、失败、同步中、新修改待上传、离线待同步均需有清楚状态。

现行逻辑为先本机保存、约 600ms 防抖上传整份状态，启动和页面重新可见时尝试拉取，回网尝试上传；没有可靠的字段级合并或服务端版本冲突协议。不得承诺「永不丢失」「实时无缝」「云端不受影响」。实现时必须修复：按账号隔离本地状态，退出/切换不串数据；旧请求不得回写到新账号；reconcile 不能篡改真实修改时间；同步中发生的新修改要补传；成功提示等待真实确认。多设备冲突要明确覆盖对象、先备份再选择，不能假装自动合并已经存在。

JSON 备份支持导出和文件导入，接受原备份包装对象或合法根状态，包含资料、日程、记录与照片。导入前校验完整结构、字段和数值，预览其覆盖影响；错误 JSON 或不完整数据不能先清空当前状态。导入后重新关联并参与后续同步。自检展示题本/课程与事项库一对一、来源 ID 无重复、三倒计时正常等结果，并显示检查中、正常、已修复、无法修复。不要把映射自检包装成全方位安全检测。

恢复初始数据必须置于独立危险区，先确认并建议导出；它会恢复默认资料及初始进度，并非删除账号。登录时重置后的状态仍可能上传覆盖云端，必须准确说明，不能写「只清本机、云端不变」。网页保留 APK 下载为次级入口；已安装 Android 内不突出重复安装。文件不存在或下载失败需反馈，不得以 HTML 回退文件伪装成 APK。没有前端历史快照恢复功能，不新增该入口。

## 五、所有页面共用的状态与 Android 实现要求

每个异步区域至少设计：初始加载、成功、有内容/空态、失败与重试；离线与登录失效分开。保存按钮有默认、按压、禁用、进行中、成功、失败，失败保留输入；字段支持焦点、错误文案和错误定位。危险操作在确认前不能执行，取消恢复原状。反馈可用轻提示和原位状态，不用成功弹窗掩盖未完成请求。

原生层目前是 AppCompatActivity + WebView，源码 minSdk 24、target/compileSdk 34；安全区、返回、文件落盘与离线来源仍有实际缺口，不能把设计当作已修复证明。实现必须按真实系统 WindowInsets 处理状态栏、切口、手势区和三键导航；必要时配合网页安全区和动态视口高度。不能仅固定 915 高或用 100vh 造成遮挡。

长表单可滚动，键盘弹出时当前字段、错误和提交入口能到达，底部主按钮不压住输入；日期、数字、密码和链接使用合适键盘。系统返回优先关闭选择器/弹层/键盘，再返回上页；未保存修改有丢弃确认，根页面退出规则明确。系统文件选择器支持图片多选和 JSON，处理用户取消、无可用应用与失效 URI。导出使用可靠的 Android 保存/分享能力，验证实际生成可再次导入的文件，不满足于 Blob 按钮点击成功。

HTTPS 在线页与 file assets 当前没有存储迁移桥，需实现统一可靠的本机数据来源或明确迁移，验证断网启动、在线转离线、回网、重启后数据和账号一致，不能只切换 HTML 后宣称离线闭环。外链课程交给合适浏览器；不靠忽略 SSL 错误作为正式联网方案。所有这些属于开发验收要求，不是现有能力声明。
